# 持久化选 SQLite 单文件

单机自部署、数据与程序同机、无跨网络访问、写入以低频配置变更和追加型用量记录为主，三条引入客户端服务器型数据库的判据都不成立。SQLite 在 WAL 模式下读写互不阻塞，备份可用 `VACUUM INTO` 产出事务一致快照。

## 备选方案

- PostgreSQL。并发写与备份能力更强，但引入独立进程、连接管理与运维成本，与单机自用不匹配
- DuckDB。分析负载引擎，原生格式同一时刻只允许一个进程写入，不适合承载应用状态
- 嵌入式 KV。redb 格式稳定但生态薄，sled 自述与主分支不同步且不支持多实例，风险高

## 影响

数据文件必须放在本机文件系统，WAL 模式依赖共享内存，放到网络文件系统会损坏数据库。备份只能用在线备份接口或 `VACUUM INTO`，不能直接拷贝文件。
