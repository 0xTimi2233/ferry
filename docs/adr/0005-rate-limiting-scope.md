# 限流只做凭证冷却与并发上限

单机自用、单副本、客户端数量极少、上游凭证数量有限，限流的目标是保护本机资源与避免无效撞墙，不是多租户公平。因此只做两件事：凭证级冷却表与在途并发上限。token 维度只用于成本可视化，不参与准入控制——只有一个上游账号时上游自己会返回 429，本地再按 token 限一次等于对同一次限流重复惩罚。

## 备选方案

- 按 token 做本地预算限流。需要事前估算预留加事后结算的账本，且与上游配额重复惩罚，在无租户竞争时没有收益
- 滑动窗口精确配额。固定窗口的边界双倍突发在自用场景无害，滑动窗口的每 key 内存与操作成本是实打实的
- IP 维度限流。反向代理部署下客户端 IP 容易坍缩为代理地址，反而会把自己限死

## 影响

并发上限与冷却表都在进程内，多副本部署时需要外部协调，但单机形态下不存在这个问题。将来若出现真实的多租户需求，需要补的是一整套额度与公平调度，不是给现有冷却表加参数。
