# 产品愿景

个人自用的 AI 网关，把散落各处的上游凭证与 AI 订阅统一收拢，让 Codex、Pi Agent 这类编码客户端只接一个入口，就能按别名调度到不同上游。

## 战略定位与子域划分

- 核心域：凭证与调度。凭证统一管理多家上游的密钥与订阅，调度决定每次请求落到哪个凭证
- 支撑域：模型目录、协议适配、计量。模型目录维护别名到别名目标的映射，协议适配负责把入站请求翻译成上游的形态，计量记录用量
- 通用域：访问校验、持久化、HTTP 服务

## 目标用户与核心诉求

- 个人开发者：手上有多家 API 密钥与 AI 订阅，希望一处管理、按模型名调度，不必为每个客户端单独改配置

## 核心能力矩阵

- 凭证管理：注册密钥凭证与订阅凭证，自动刷新订阅令牌，标记健康状态
- 模型调度：以别名组织上游，按轮询、加权或优先策略选取凭证，失败按重试策略切换，会话保持粘性
- 协议兼容：固定支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini 四套基准协议，其余上游按变体接入
- 用量计量：记录请求次数、token 用量与折算金额，按天聚合成绿块视图
- 管理界面：概览、凭证、模型、日志、设置

## 主干业务生命周期

1. 接入：客户端携带访问密钥发起请求，校验身份后放行
2. 解析：解析入站协议，按别名取得别名目标
3. 调度：按别名策略选取可用凭证，必要时按重试策略切换
4. 转发：把请求转换为上游协议的形态，发往上游
5. 回流：响应转换为客户端协议的形态返回，同时发布用量事件
6. 计量：订阅用量事件，落账并按天聚合

## 非目标边界

- 多租户与账号体系
- 支付与充值
- 自动路由，二期评估
